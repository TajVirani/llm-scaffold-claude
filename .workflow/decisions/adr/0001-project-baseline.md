# Project baseline: host-neutral core behind thin host shims
<!-- verified_at_commit: 0a662df5d1046bd2984be858e813992a7fb36eb7 -->

This repo builds a workflow that several coding agents must run, so the workflow lives once in a host-neutral `.agents/` core and each host reaches it through a thin shim: `.claude/` is symlinks plus `settings.json`, and `.codex/` config and agent tomls are generated by `install.sh`. Hooks are adapters over skill scripts, all state is files in git, and `install.sh` distributes exactly what `.agents/install-manifest.txt` lists. No starter. Everything else a baseline usually settles (ID scheme, auth, API style, deployment, caching, search, real-time, logging destination) is not in scope for a tooling repo.

## Deferred

- CI: one contributor; running `tests/run-all.sh` by hand before reporting done is the gate until others contribute.
- `shfmt`: adopting it means a repo-wide reformat, and 2-space indentation already holds without it.
- Tests for `drift.ts`, `collect_change_data.py`, `validate_mermaid.mjs` and `audit_scope.sh`: they are off the hook path.
- Missing header blocks (6 scripts) and missing skill trigger clauses (4 skills): fixed when each file is next touched.
- `.agents/README.md` rewrite into a short index of the distribution unit, with the data-structure-audit bundle note moved into that skill.
- A version-pin policy for host CLIs (Claude Code, codex-cli): today comments carry "verified against" stamps.
